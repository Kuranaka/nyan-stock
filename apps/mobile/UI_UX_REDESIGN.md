# にゃんストック UI/UX 再設計

## 1. 再設計の結論

にゃんストックを「在庫を入力・閲覧するアプリ」から、次の状態をつくる生活支援アプリへ再定義する。

> 今日やることが分かり、買い忘れを防げて、補充の記録が10秒で終わる。

コア体験は次の一本に絞る。

```text
用品を登録
  → 残り日数が分かる
  → なくなる前に気づく
  → 購入する
  → 補充を記録する
  → 次回の買い時が更新される
```

評価軸は「表示できる情報量」ではなく、買い忘れを防ぐまでの行動数と、記録を続ける負担の小ささとする。

## 2. 現在ある機能の棚卸し

### 初回・アカウント

- Google / Apple / ゲストで開始
- ペットプロフィール登録
- 複数ペット・8種類のペット種別
- Plusプラン

### 在庫

- 商品マスタ検索・手入力
- 複数ペットで同じ用品を共有
- 4種類の残り日数推定
  - 使用量
  - 使い切る日数
  - 購入頻度
  - 推定なし
- 残量・残り日数の補正
- ローカル通知

### 購入・補充

- Amazon / 楽天 / Yahoo / 任意URL
- 購入リンク検索
- 補充による在庫周期の更新
- 購入履歴・価格編集

### 振り返り

- 月額・年額費用目安
- 今月実績
- カテゴリ別内訳
- 6か月推移

### 共有・運用

- 家族共有、招待コード、Realtime更新
- 問い合わせ・商品画像報告
- レビュー依頼
- 法務、広告、データ初期化

機能そのものは十分に揃っている。主な問題は、日常の高頻度タスクと、設定・分析などの低頻度タスクが同じ強さで表示されていることにある。

## 3. ユーザーの利用場面

| 頻度   | ユーザーの目的                     | UIが優先すべきこと                             |
| ------ | ---------------------------------- | ---------------------------------------------- |
| 初回   | ペットと最初の用品を登録したい     | 必須入力を最小化し、最初の残り日数まで案内する |
| 日次   | 今日買う物があるか知りたい         | 全ペット横断で「要対応」だけを先に見せる       |
| 購入時 | いつもの購入先を開きたい           | 商品詳細を探さず、対象カードから購入へ進める   |
| 補充時 | 在庫を更新したい                   | 前回値を初期入力し、数秒で保存できる           |
| 週次   | 7日以内になくなる用品を確認したい  | 「そろそろ」をまとめ、未設定品も見直せる       |
| 月次   | 支出を振り返りたい                 | 実績と予測を混ぜず、選択月に統一して表示する   |
| 低頻度 | 通知・共有・アカウントを設定したい | 設定トップから目的別の子画面へ進める           |

## 4. 現状の主要な摩擦

1. ホームが全商品の管理一覧になっており、「今日何をするか」が弱い。
2. ペットを1匹選ぶ前提で、家庭全体の在庫切れを横断確認できない。
3. 日数未設定の商品がサマリーに現れず、価値が出ていない状態に気づきにくい。
4. 商品登録が検索・在庫計算・通知・価格・4つの購入URL・メモを一画面に抱えている。
5. 商品詳細が残量調整・編集・購入・URL設定・報告・補充・履歴・削除を一画面に抱えている。
6. 「購入先を見た」と「購入した」と「届いて補充した」が同じ流れに混在している。
7. 高頻度の補充記録が詳細画面の下部にあり、入力と確認が多い。
8. 設定が通知・共有・アカウント・Plus・法務・問い合わせ・削除をすべて展開している。
9. 旧配色は主要ボタンと状態色のコントラストが不足していた。
10. 下部ナビがアイコンだけで、Stackの戻る操作との役割が分かりにくかった。

## 5. ゼロベースの情報設計

最終的な主ナビゲーションは次の4領域とする。

1. **ホーム**
   - 今日の要対応
   - 今後7日
   - 日数未設定
   - 最近の記録

2. **用品**
   - 全用品
   - 検索
   - ペット・カテゴリ・状態で絞り込み
   - 用品追加

3. **記録**
   - 補充
   - 購入
   - 履歴
   - 費用実績・目安

4. **設定**
   - ペット
   - 通知
   - アカウントとバックアップ
   - 家族共有
   - Plus
   - ヘルプ・法務

現行構造では専用の「用品」「記録」タブがまだないため、今回の実装は在庫画面をホームとして再構成し、追加・費用・設定への明示的な下部導線を残している。

## 6. 新しいホーム

情報の優先順位を次の順にする。

1. 在庫切れ・残り3日以内
2. 残り4〜7日
3. 残り日数未設定
4. 在庫に余裕がある用品

設計ルール:

- 複数ペットがいる場合は「みんな」を初期表示とする。
- 件数だけでなく、意味と次の行動を文章で示す。
- 正常在庫は初期状態で折りたたみ、安心を先に伝える。
- 在庫カードは残り日数を主役にし、詳細ボタンは置かずカード上部を入口にする。
- 状態に応じて「買い足す」と「補充を記録」の優先度を変える。
- 色だけで状態を伝えず、文言・数値・選択記号を併用する。
- 共有データを読めない場合も、エラーで画面全体を失わず再試行できるようにする。

## 7. 初回ジャーニー

目標フロー:

```text
価値を理解
  → 無料で始める / ログイン
  → ペット名を登録
  → 最初の用品を選ぶ
  → 「だいたい何日もつ？」を回答
  → 次回目安を表示
  → その文脈で通知許可
```

初回の必須項目は原則として以下の3点にする。

- ペット名
- 商品
- おおよその使用周期

誕生日、体重、性別、画像、価格、購入URL、個別通知、メモは「あとで設定」に退避する。

## 8. 商品登録の再設計

長尺フォームを2段階に分ける。

### Step 1: 商品を見つける

- 商品検索
- 手入力
- バーコード（実装後）

### Step 2: 買い時の目安を決める

内部の計算方式名をそのまま見せず、ユーザーの言葉で質問する。

- だいたい○日で使い切る
- 内容量から詳しく計算する
- 補充間隔から学習する
- 今は予測しない

登録直後から価値を出すため、初期推奨は「だいたい○日で使い切る」とする。保存前に「次は○月○日ごろ」のプレビューを表示する。

価格、購入URL、通知の細かな日数、画像URL、メモは詳細設定へ移す。

## 9. 購入と補充を分ける

用語と状態を明確に分離する。

- **買う**: 外部ストアへ進む
- **購入済みにする**: 購入日・価格・購入先を履歴へ残す
- **補充した**: 在庫周期を更新する
- **残量を直す**: 予測誤差を補正する

外部ストアから戻っただけで補充フォームを開かない。必要なら「購入しましたか？」を軽く確認し、「見ただけ」も選べるようにする。

補充は共通のボトムシートまたは専用の短い画面にし、次を初期入力する。

- 日付: 今日
- 価格: 前回値
- 補充方法: 前回選択

保存後は「次は○日後の予定」とUndoを表示する。

## 10. 商品詳細の分割

商品詳細は主行動を上部へ固定し、次の3領域へ分ける。

1. **概要**
   - 残り日数
   - 次回目安
   - 対象ペット
   - 買う / 補充 / 残量修正

2. **履歴**
   - 購入・補充のタイムライン

3. **商品設定**
   - 計算方法
   - 通知
   - 価格
   - 購入先
   - メモ
   - 削除

画像報告と削除は主画面から退避し、メニューまたは設定画面に置く。

## 11. ビジュアル方針

コンセプトは「Warm Utility / ペットとの暮らしのストック手帳」。

- 生成りの背景と白い面で、暮らしになじむ落ち着きをつくる。
- 操作色は十分に濃いテラコッタを使う。
- 明るい黄橙はロゴや装飾へ限定する。
- 状態色とブランド色を分離する。
- 太字、カード、塗りボタンを多用せず、意味の階層をつくる。
- 操作領域は原則48px、最低44pxとする。

主要トークン:

| 用途       | 色        |
| ---------- | --------- |
| 背景       | `#FBF8F2` |
| カード     | `#FFFFFF` |
| 本文       | `#2D2823` |
| 補足       | `#6B6258` |
| 操作       | `#8F4A22` |
| 操作・濃色 | `#713817` |
| 境界       | `#E7DED3` |
| 在庫あり   | `#2F6E4F` |
| そろそろ   | `#755000` |
| もうすぐ   | `#963918` |
| 在庫切れ   | `#991F2B` |

## 14. 検証指標

リリース後は次を確認する。

- 初回開始から最初の用品登録完了までの時間
- 最初の用品登録完了率
- 日数未設定のまま残る商品の割合
- 通知から購入先を開くまでのタップ数
- 補充記録にかかる時間と完了率
- 7日以内に同じ商品を重複購入した割合
- 1週間後 / 4週間後の継続率
- 家族共有開始後の同期エラー率

最重要指標は、補充記録の件数そのものではなく、「買い忘れが減った」と感じるユーザーの割合とする。
