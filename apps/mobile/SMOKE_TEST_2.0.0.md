# にゃんストック 2.0.0 スモークテスト

このファイルを、2.0.0の手動動作確認とGo / No-Go判定の正本とします。
チェックは、対象ビルドで実際に確認し、証跡を残した項目だけを`[x]`にします。

公開情報と外部サービスの設定は
[APP_STORE_SUBMISSION_CHECKLIST.md](./APP_STORE_SUBMISSION_CHECKLIST.md)、
リリース概要は[RELEASE_2.0.0.md](./RELEASE_2.0.0.md)を参照します。

## 判定レベル

- **P0**: 失敗または未確認なら提出しない。データ消失、プライバシー、認証、課金、審査、
  主要導線に関わる項目。
- **P1**: 公開前に原則修正する。回避手段があり、データ・課金・プライバシーへ影響しない場合だけ、
  影響と対応予定を記録してリリース責任者が判断する。

## 対象ビルドと証跡

テスト開始時に記入します。

- Git commit:
- iOS version / build:
- EAS build URL:
- Simulator機種 / iOS:
- TestFlight実機 / iOS:
- Supabase project:
- RevenueCat Offering確認日時:
- AdMob / UMP設定確認日時:
- 実施者 / 実施日:
- 証跡フォルダまたはチケット:

テストデータは架空のペット名・商品名・画像だけを使用します。スクリーンショットへ実在する
個人情報、商品購入履歴、店舗アカウント、通知内容を写しません。

## 開始条件

- [ ] リリース候補と同じcommitからSimulator用ReleaseビルドとTestFlightビルドを作成した。
- [ ] `npm run verify:release`、`npx tsc --noEmit`、`npm run lint`、
  `npx expo export --platform ios`がリリース候補commitで成功した。
- [ ] TestFlightビルドでは、EAS production環境のSupabase、RevenueCat、AdMob本番設定を使用し、
  テスト用キー、サンプル広告ID、仮URLが混ざっていない。
- [ ] テスト開始前の既知問題と、テスト中に作成するアカウント・共有スペースの削除方法を確認した。

## 第1段階: Simulator

Simulatorでは、画面構成、ローカルデータ、予測ロジック、基本導線を先に確認します。
通知、Apple / Google認証、課金、広告同意、アカウント削除の本番連携は、
この段階だけで合格にせずTestFlight実機でも確認します。

### P0

- [ ] **SIM-P0-01 初回導線**
  アプリデータを消した状態で起動し、オンボーディングから匿名ゲストを開始できる。
  説明文はメールアドレス等の入力が不要であることと、匿名アカウントを作成することを正しく伝える。

- [ ] **SIM-P0-02 ペット登録と切り替え**
  対応する複数のペット種別を登録でき、1匹だけでも「表示するペット」とデフォルトアイコンが表示される。
  誕生日、体重、性別、メモは「プロフィール詳細を追加」内にあり、未入力でも保存できる。
  「○項目を設定済み」のような不要な件数表示がない。

- [ ] **SIM-P0-03 商品登録**
  必須項目だけで登録でき、JANコード検索がない。購入URLは折りたたみ／トグル内にまとまり、
  URL未入力でも登録できる。カテゴリは共通カテゴリとして選択でき、商品詳細から変更できる。
  商品マスタ由来の商品を登録した場合も、カテゴリが共通カテゴリへ正しく変換される。

- [ ] **SIM-P0-04 補充履歴からの学習**
  初回の商品登録日・初回購入日だけでは予測を開始しない。1件目の「補充を記録」後も
  「学習中」のままで、2件目の補充履歴がたまった時点から予測を開始する。
  計算間隔には「補充を記録」で入力した購入日だけが使われ、初回購入日を含めない。

- [ ] **SIM-P0-05 在庫の状態と並び順**
  「学習中」は「余裕あり」より上に表示される。「日数表示なし」フィルタで対象だけを絞り込める。
  日数未設定の商品へ設定を強制するカードや文言がなく、補充による自動学習を妨げない。

- [ ] **SIM-P0-06 補充と履歴の整合性**
  補充を記録すると、入力した購入日・価格・数量が1件だけ履歴へ追加される。
  編集、再起動、月をまたぐ表示でも重複や消失がなく、価格未入力は費用実績から除外される。

- [ ] **SIM-P0-07 費用画面**
  今月の実績、月額予測、今後30日の買い足し見込み、カテゴリ／商品内訳が同じデータから整合して表示される。
  周期または価格が不足する商品は「未計算」として説明され、誤った0円や予測額に含めない。

- [ ] **SIM-P0-08 法務画面**
  設定からプライバシーポリシー、利用規約、アフィリエイト表記を開ける。
  商品マスタ改善用情報を送信する説明・設定・同意導線が残っていない。
  購入リンク付近にはアフィリエイトリンクを含む場合がある旨を表示する。

- [ ] **SIM-P0-09 再起動とデータ分離**
  再起動後も選択中のペット、商品、補充履歴が維持される。ペットを切り替えると
  そのペットの用品だけが表示され、別のペットや共有スペースのデータが混ざらない。

- [ ] **SIM-P0-10 データ初期化**
  非共有時にデータ初期化すると、ペット・用品・購入履歴・予約通知だけが削除され、
  Supabaseの同一ユーザーID、ログイン状態、Plus状態を維持したまま空の在庫画面へ戻る。
  共有中は初期化が実行されず、共有を解除してから行う案内が表示される。

### P1

- [ ] **SIM-P1-01 小さい画面と文字サイズ**
  オンボーディング、在庫、商品登録、商品詳細、費用、設定で、不自然な改行、
  文字切れ、横スクロール、下部タブとの重なりがない。

- [ ] **SIM-P1-02 iPadレイアウト**
  13 inch iPad Simulatorで主要画面を確認し、過度な横伸び、操作要素の欠落、
  モーダルの画面外表示、回転後の崩れがない。

- [ ] **SIM-P1-03 権限拒否**
  通知と写真へのアクセスを拒否しても登録済みデータを失わず、設定から後で変更できる。
  拒否後に同じ許可ダイアログを不必要に繰り返さない。

- [ ] **SIM-P1-04 空・上限・エラー状態**
  ペット0件、商品0件、価格未入力、URL不正、オフライン、登録上限の各状態で、
  次に取る行動が分かり、操作不能にならない。

## 第2段階: TestFlight実機・Sandbox

TestFlightでは、提出候補そのものを本番相当の外部設定で確認します。
Simulatorで合格した項目も、データや外部連携に関わる主要導線は再確認します。

### P0

- [ ] **TF-P0-01 本番構成**
  version / build number、Supabase project、認証redirect、RevenueCat公開SDKキー、
  AdMob iOS App IDとバナーIDが提出対象の値である。開発用メニューとデバッグ用シードが表示されない。

- [ ] **TF-P0-02 商品マスタ改善用送信の停止**
  本番Supabaseへ
  `20260726000004_disable_mobile_product_master_suggestions.sql`を適用済みである。
  2.0.0から送信処理・通信が発生せず、旧版アプリからの新規送信も拒否される。
  既存データを残す場合は保管目的と削除条件がプライバシーポリシーと運用に一致する。

- [ ] **TF-P0-03 匿名ゲストとApple / Google認証**
  匿名ゲスト、Apple、Googleの各導線でログインできる。ゲストから認証を追加した場合、
  既存のペット・用品・補充履歴・共有状態を失わず、到達不能な匿名アカウントや画像を残さない。
  ログアウト後に別ユーザーのデータが表示されない。

- [ ] **TF-P0-04 アカウント削除と画像削除**
  匿名ゲスト、Apple、Googleで「設定 > データ管理 > アカウントを削除」が完了する。
  `cats/{userId}/{ownerId}/...`と`products/{userId}/{ownerId}/...`の画像を含む対象ユーザーのデータだけが削除される。
  削除後の再起動で削除済みセッションへ戻らず、同じ認証情報で再度開始しても旧データが復元されない。
  Apple / Google側の連携解除・失効が必要な場合は、その処理と案内も確認する。

- [ ] **TF-P0-05 月額Plus購入**
  RevenueCat Current Offeringの月額商品、表示価格、期間がApp Store Connectと一致し、
  Sandbox購入後に`nyanstock_plus` entitlementが有効になる。二重購入や完了前の有効化がない。

- [ ] **TF-P0-06 年額Plus購入**
  RevenueCat Current Offeringの年額商品、表示価格、期間がApp Store Connectと一致し、
  Sandbox購入後に`nyanstock_plus` entitlementが有効になる。月額と年額の選択状態が取り違わない。

- [ ] **TF-P0-07 復元・管理・失効**
  購入復元、サブスクリプション管理、期限切れ／解約後の権限反映を確認する。
  復元失敗時は誤ってPlus扱いにせず、再試行可能な案内を表示する。

- [ ] **TF-P0-08 広告、UMP、ATT**
  UMPの同意状態とATTの許可／拒否に応じ、パーソナライズ広告、非パーソナライズ広告、
  限定広告の挙動が設定と申告に一致する。追跡を許可していない状態で追跡を開始しない。
  Plus有効時は広告を読み込まず表示せず、広告を表示しない利用者へ不要な広告同意／ATT要求を出さない。
  Release `.app` の `GADDelayAppMeasurementInit` がtrueで、起動直後からUMP・ATT完了まで
  Google Mobile Adsのapp measurement通信が始まらないことも確認する。

- [ ] **TF-P0-09 通知**
  初回の通知説明からiOSの許可ダイアログへ進める。許可時は予定した時刻にローカル通知が届き、
  拒否時はアプリを利用し続けられる。削除済み商品・アカウントの通知が残らない。

- [ ] **TF-P0-10 外部購入リンク**
  購入先URLを安全に外部ブラウザで開き、不正URLを拒否する。
  購入操作の近くにアフィリエイト表記があり、戻った後に補充記録を続けられる。

- [ ] **TF-P0-11 法務・申告の一致**
  アプリ内と公開Webのプライバシーポリシー、利用規約、アフィリエイト表記がログインなしで開ける。
  Supabase、RevenueCat、AdMob、通知、画像、認証、アカウント削除、商品マスタ送信停止の説明が
  実装およびApp Store ConnectのApp Privacy回答と一致する。

- [ ] **TF-P0-12 ストア画像**
  2.0.0の提出ビルドから、架空データでiPhone 6.9 inchとiPad 13 inchのスクリーンショットを作成した。
  Appleの現行仕様に合う寸法・枚数で、古いUI、透明背景、Simulator枠、開発表示、実在の購入情報がない。
  月額商品と年額商品の審査用スクリーンショットも各商品へ登録した。

### P1

- [ ] **TF-P1-01 主要導線の実機再確認**
  初回起動、ペット登録、商品登録、補充2件からの学習、在庫フィルタ、費用、商品詳細のカテゴリ変更を
  実機で一巡し、クラッシュ、二重保存、著しい待ち時間がない。

- [ ] **TF-P1-02 オフライン復帰**
  一時的な通信断でローカル操作が失われず、復帰後に重複同期や別ユーザーへの混入がない。

- [ ] **TF-P1-03 広告・課金エラー表示**
  広告在庫なし、RevenueCat一時エラー、購入キャンセル、Sandbox接続失敗で
  画面が塞がらず、課金済みと誤表示しない。

- [ ] **TF-P1-04 App Review再現手順**
  [app-store-metadata.md](../../docs/app-store-metadata.md)のReview Notesだけで、
  審査担当者が匿名ゲスト、共有、Plus購入・復元、アカウント削除へ到達できる。
  必要な共有コードまたは確認用アカウントをApp Store Connectへ安全に追記した。

## Go / No-Go

### Go

次をすべて満たした場合だけ、App Store審査へ進みます。

- [ ] SimulatorとTestFlightのP0がすべて合格し、未確認が0件である。
- [ ] P1がすべて合格している。または、データ、課金、プライバシー、認証、審査に影響しない
  例外だけが、影響・回避策・修正予定とともに承認されている。
- [ ] 自動検証を最終commitで再実行し、結果とbuild番号を証跡へ保存した。
- [ ] [APP_STORE_SUBMISSION_CHECKLIST.md](./APP_STORE_SUBMISSION_CHECKLIST.md)がすべて完了している。
- [ ] App Store Connectへ登録した文言、価格、法務URL、App Privacy、スクリーンショットが
  TestFlightで確認したビルドと一致する。

### No-Go

次のいずれかに当てはまる場合は提出しません。

- P0が1件でも失敗または未確認。
- 商品マスタ改善用データを新規送信できる、または停止migrationが本番未適用。
- 初回購入日を予測へ含める、補充履歴2件未満で予測を開始する、履歴が重複・消失する。
- 認証切り替えでデータを失う／孤立アカウントを残す、アカウント削除後にセッション・画像・通知が残る。
- RevenueCatの商品・価格・entitlementがApp Store Connectと一致しない、購入・復元を確認できない。
- UMP / ATT、広告表示、Plusの広告非表示、Privacy Manifest、App Privacyの説明が一致しない。
- 法務URLが未公開またはログイン必須、仮の問い合わせ先や古い2.0以前の文言が残る。
- iPhoneまたはiPadの提出画像、月額または年額商品の審査用画像が不足している。
