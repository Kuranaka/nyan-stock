## Simulator / ローカルデータ

### P0

- [ ] **SIM-P0-01 旧データ移行**
  2.0.0で保存したペット、在庫、購入履歴、設定、ログイン状態を残したまま2.0.1へ更新し、全データを表示できる。再起動後も消失や重複がない。

- [ ] **SIM-P0-02 破損データの安全な復旧**
  検証用に壊した対象AsyncStorage値を読み込んでもクラッシュせず、安全な初期値へ復旧する。元の値は`recovery-backup`へ退避され、将来versionのデータは上書きされない。

- [ ] **SIM-P0-03 補充の一括保存**
  補充を1回保存すると在庫量・購入日と購入履歴が同時に更新される。失敗を再現した場合、在庫だけ、または履歴だけが残らない。

- [ ] **SIM-P0-04 基本導線**
  ペット登録、在庫作成・編集・削除、補充、履歴、費用、通知設定、購入リンク、データ初期化が正常に動作する。削除と初期化の確認ダイアログが維持されている。

### P1

- [ ] **SIM-P1-01 エラー表示**
  費用、月別内訳、購入履歴で読み込みに失敗した場合、内容を説明するメッセージと再読込ボタンが表示される。

- [ ] **SIM-P1-02 主要画面レイアウト**
  在庫詳細、購入履歴、費用、設定で文字切れ、横スクロール、操作不能なボタンがない。

## TestFlight / 家族共有

### P0

- [ ] **TF-P0-01 migrationと権限**
  2.0.1から共有中の補充・削除が成功する。非参加ユーザーは対象RPCを実行できず、別householdのデータを変更できない。

- [ ] **TF-P0-02 別端末の在庫を巻き戻さない**
  端末Aが商品Aを表示中に端末Bで商品Bを追加し、その後端末Aで商品Aを削除しても商品Bが残る。購入履歴のスナップショットも維持される。

- [ ] **TF-P0-03 共有ペット削除**
  複数ペットに紐づく商品から1匹を削除すると商品は残り、残りのペットへ正しく紐づく。そのペットだけの商品は削除され、無関係の商品は変更されない。

- [ ] **TF-P0-04 1,000件超の履歴**
  共有スペースに1,001件以上の購入履歴を用意し、先頭・1,000件境界・最終件をすべて表示できる。再読込後も欠落、重複、並び順の異常がない。

- [ ] **TF-P0-05 共有補充の原子性**
  端末Aで補充を保存し、端末Bで在庫更新と履歴追加を同じ更新として確認できる。通信失敗時に片方だけが保存されない。

- [ ] **TF-P0-06 オフライン表示**
  共有中に通信を切って在庫、履歴、費用を開くと、共有データはオフライン表示できない旨と再読込が表示される。通信復帰後の再読込で最新状態へ戻る。

- [ ] **TF-P0-07 認証とアカウント境界**
  ゲスト、Apple、Googleの対象導線、ゲストからのidentity linking、ログアウト、アカウント削除が既存データや別ユーザーのデータを漏らさず動作する。

- [ ] **TF-P0-08 課金・広告・法務**
  RevenueCatの商品・価格・復元、Plusの広告非表示、UMP / ATT、プライバシー・利用規約・アフィリエイト表記が提出設定と一致する。

### P1

- [ ] **TF-P1-01 同時更新と再接続**
  2端末で別の商品を更新し、Realtime再取得後に両方の変更が残る。一時的な通信断と再接続で重複や別ユーザーへの混入がない。

- [ ] **TF-P1-02 大量データ時の応答**
  1,001件以上の履歴を持つ共有スペースで、在庫・履歴・費用画面がクラッシュせず、再試行可能な時間内に表示される。

## Go / No-Go

### Go

- [ ] P0がすべて合格し、未確認が0件である。
- [ ] P1が合格、またはデータ・認証・課金・プライバシーへ影響しない例外だけが承認されている。
- [ ] 本番Supabaseへ新migrationを適用済みである。
- [ ] EAS remote build番号とApp Store Connectの既存番号を確認済みである。
- [ ] [APP_STORE_SUBMISSION_CHECKLIST.md](./APP_STORE_SUBMISSION_CHECKLIST.md)が完了している。

### No-Go

- migration未適用、またはRPCのmembership制約を確認できない。
- 別端末が追加・更新した在庫または履歴を削除操作が巻き戻す。
- 補充後に在庫と履歴の片方だけが保存される。
- 1,001件以上の共有履歴で欠落や重複が発生する。
- オフライン時に空データを正常データとして見せる、または操作不能になる。
- 2.0.0からの更新で端末内データが消失する。
