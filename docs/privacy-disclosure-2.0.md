# にゃんストック 2.0 プライバシー申告

更新日: 2026年7月26日

この文書は、バージョン2.0の現行実装、アプリ内プライバシーポリシー、Web版プライバシーポリシー、iOS Privacy Manifest、App Store ConnectのApp Privacy回答を一致させるための提出用メモです。

## 現行実装のデータ取扱い

- ゲスト開始時も、Supabaseに匿名ユーザーIDを作成します。メールアドレス等の入力は不要です。
- 共有を使わないペットプロフィール、在庫、購入履歴は原則として端末内に保存します。
- 利用者が設定したペット・商品画像は、共有の利用有無にかかわらずSupabase Storageへアップロードし、公開URLで表示します。
- GoogleまたはAppleログインでは、認証に必要なユーザーID、メールアドレス、表示名、プロフィール画像を扱う場合があります。
- 共有機能では、共有スペースID、ペットプロフィール、在庫、購入履歴をSupabaseへ保存します。
- 商品検索、価格確認、アフィリエイトリンク生成では、検索語・商品URL・検索結果を、ユーザーIDを含まない共通キャッシュとして保存する場合があります。ただし、認証済みユーザーIDと同一リクエスト内で処理し、運用ログ等により利用者へ紐付けられる可能性があるため、App Store Connectでは検索履歴・閲覧履歴をユーザーに紐付く情報として保守的に申告します。不正利用防止と利用回数の制御のため、ユーザーID別の利用回数と利用時間帯も保存します。
- 現行版は、手入力の商品名、カテゴリ、購入リンク等を商品マスタ改善用の収集先へ新規送信しません。ただし、旧版から過去に送信された商品名、カテゴリ、購入リンク、画像URL、利用者識別子等は、新規収集の停止後も現時点で保存されている場合があります。これらは、アカウント削除または利用者からの削除依頼により削除の対象となります。共有同期を利用する場合に登録した商品情報は、ほかの在庫情報と同様に共有スペースへ保存します。利用者が設定した画像は、前記のとおり共有の利用有無にかかわらずSupabase Storageへ保存します。
- アプリ内のお問い合わせでは、送信内容と対応・送信回数の制御に必要なユーザーID、認証プロバイダ情報、共有スペースID、送信時間帯等を保存します。
- アプリ内のお問い合わせの新着メール通知にはResendを利用します。メールへは問い合わせ本文を含めず、問い合わせ識別子と受信日時等の最小限の情報だけを送信します。
- Plusの購入・復元・購読状態はRevenueCatで処理します。SupabaseのユーザーIDやメールアドレスはRevenueCatへ設定していません。
- 無料プランではGoogle AdMobを利用します。同意状況に応じ、IDFA等の端末識別子、IPアドレスから推定されるおおよその位置、広告イベント、操作・診断情報が処理される場合があります。
- iOSでは広告読込前にUMPとATTを処理し、必要な同意がない場合は非パーソナライズ広告、限定広告、または広告なしになります。
- Googleログインで取得したメールアドレス、表示名、プロフィール画像は、共有スペースへ参加した場合も共有相手に表示しません。共有相手に表示するのは、アプリ内で入力した参加者名と共有スペース内のデータです。

## 保持・削除と委託先の整理

- 端末内データはアプリの利用中、利用者が削除するまで保持し、データ初期化またはアプリ削除で削除します。
- 認証情報、個人用クラウド同期データ、アップロード画像は、アカウントの存続中または機能提供に必要な間保持し、アカウント削除の対象とします。他の参加者がいる共有スペースのデータは、参加者への機能提供に必要な間残ります。
- 検索語・商品URL・検索結果は共通キャッシュとして機能上必要な間保持し、有効期間後は再利用せず、運用上合理的な期間内に削除または匿名化します。ユーザー別の利用回数と利用時間帯は、アカウントの利用中ならびに利用制限・不正防止に必要な間保持します。
- 問い合わせ、関連する利用制限記録、旧版から過去に送信された商品マスタ改善用データは、問い合わせ・再問い合わせ、紛争対応、不正防止、サービス運用に必要な期間保持する場合があります。アカウント削除または削除依頼時は、法令・安全管理上必要なものを除き削除対象とします。
- 削除後もバックアップまたはセキュリティ・運用ログに合理的な期間複製が残る場合があります。その間は復旧、安全管理、法令・紛争対応以外に利用せず、バックアップ・ログの更新に応じて削除または匿名化します。法令上の保存義務がある情報は必要な期間保持します。
- Supabase、RevenueCat、Resend、広告SDK、外部の商品検索サービスには必要な範囲で取扱いを委託します。委託先には目的外利用を行わず公開ポリシーと同等以上の保護を行うことを求め、契約その他の適切な手段で取扱状況を確認・監督します。

## 提出前に残る追跡ドメイン確認

現行実装は、利用者がATTを許可した場合にGoogle Mobile Ads SDKがIDFAを広告・効果測定へ利用できる構成です。同梱SDKのPrivacy ManifestはDevice IDを`tracking = true`と申告しています。

一方、Google Mobile Ads SDK 13.5.0およびGoogle公式配布の13.7.0に含まれるPrivacy Manifestには、`NSPrivacyTrackingDomains`の確定一覧がありません。推測したドメインを登録せず、提出候補の実機通信計測またはGoogleへの確認で、追跡に使う全ドメインを確定します。確定後にアプリのPrivacy Manifestを`NSPrivacyTracking = true`とし、同じファイルへ全`NSPrivacyTrackingDomains`を追加します。

この確認が完了するまで、Privacy Manifestの追跡項目は公開ブロッカーです。ドメイン未確定の現段階では`PrivacyInfo.xcprivacy`を推測で変更せず、確認完了前にApp Storeへ提出しません。App Store Connectでは、現行実装どおりDevice IDを「トラッキングに使用」と回答します。
